# Local no-progress guard (M4)

The opt-in caller `scripts/loop_guard.py` adds a ledger around the [v1 session controller](local-session-controller.md). The v1 caller, schemas and receipts retain their behavior. Calling the v1 CLI directly bypasses this guard. This is local file coordination; it does not dispatch agents, models or tools.

`init` creates an explicit caller-declared lineage and numeric attempt budget in an external ledger. Keep each returned head outside that ledger. Supply that exact head to subsequent `observe`, `review`, `check` and `prepare` calls. Immutable manifest-backed events preserve raw failure bytes, declared normalization rules, current task bindings, progress evidence, decisions and reservations. Missing history, wrong head, partial event, lock or inconsistent hash chain fail closed. A reservation consumes budget before v1 prepare; preparation failure does not refund it.

`check` proposes an initial attempt or bounded retry, stops repeated no-progress/budget exhaustion, or waits for evidence/review. Changing task ID, goal revision, model or timestamp does not reset the selected lineage budget. Source revision changes alone do not establish semantic progress. Current source/evidence pins must validate; historical snapshots remain historical. A different operation/resource/criterion is distinguished, rather than treated as the same proven cause. Independence remains caller-declared; no project-wide dependency closure or omitted-history discovery is implemented.

Progress records identify evidence and a relevant change. Review records bind that candidate, its prior observation, ledger head and exact evidence. An operator must actually inspect the delta before explicitly selecting a review event with `--root-review`. Reviewer names, PASS labels and booleans do not authenticate anyone. Even a selected review yields only a local retry recommendation: `authority_granted`, `authenticated_review` and `full_completion` remain false.

`trace-check --trace` inspects a caller-declared ordered DAG with pinned input/output/criterion evidence. It reports first evidenced violations whose transitive predecessors are evidenced satisfied. Independent branches are evaluated separately. Missing observations remain UNRESOLVED; hypotheses and counterevidence remain separate from observed facts, and confirmed root cause stays unknown.

Use `--help` on the caller and subcommands for concrete arguments. New workloads need their own scope/source/test pins and applicability review. The command does not silently reinterpret legacy RETRY/state contracts or grant execution authority. Existing state protocol, six identities, REA–IDA ownership, historical FAIL and global gates remain unchanged.

Limits: cooperative single-writer lock; point-in-time path/freshness checks; no hostile-race sandbox, authenticated identity, adversary-resistant history, global call/time/cost cap, external-worker control or absolute loop prevention. A caller can misdeclare lineage, prerequisite, failure family, normalization or semantic relevance. Hash/schema validity proves consistency only. Native/provider/cloud/training/W4 and upstream runtime adapters remain outside this local implementation.
