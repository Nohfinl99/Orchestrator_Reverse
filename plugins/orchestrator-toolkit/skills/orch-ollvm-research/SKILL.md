# Bounded catalogue research

Treat awesome-ollvm as a curated link list spanning obfuscators, OLLVM-related work, and IDA deobfuscation plugins. It is a discovery index, not a tool, dependency manifest, endorsement, or complete survey.

1. Reuse authorization already given for this same research scope; ask only if materially needed scope information is missing. Convert the task into a bounded need (for example, identify a candidate for a specific OLLVM flattening pattern or compare documented support for a particular IDA version). Search only the relevant catalogue sections and select a small number of candidates.
2. For each candidate, follow its link to the actual repository or primary documentation. Record exact URL, commit/release, date checked, relevant source locator, stated purpose, supported inputs/versions, and known limitations. Verify license and notices at that candidate's exact revision separately; the catalogue does not transfer rights.
3. Distinguish catalogue text from verified project claims and from your inference. Check whether the linked project still exists, whether the linked description matches the task, and whether a source or artifact is actually available. Preserve conflicting or missing information as UNKNOWN.
4. Compare candidates against the target's architecture, compiler/obfuscator family, IDA/Hex-Rays version, and required transformation. A project name or catalogue category alone is not evidence of applicability or correctness.
5. Do not auto-clone, install, build, or execute a linked project. Those are separate actions requiring task scope, exact revision, rights review, and appropriate environment authorization. If execution is separately authorized, retain a clean input, isolated working copy, exact configuration, logs, hashes, and before/after semantic evidence.
6. Return a short candidate table with source locators, fit, caveats, rights/version status, and next evidence needed. Do not claim the catalogue itself performed analysis or validation.

## Orchestrator boundaries

Keep the existing six identities and REA–IDA ownership. Research notes do not create an adapter, admitted knowledge, consumer ACK, or gate transition. Small models may do bounded link/source search and extraction; use a high-capability reviewer for difficult semantic claims. The root/owner and independent reviewer assess semantic claims and any state change under existing project workflow. Preserve historical FAILs and record discrepancies as issues.
